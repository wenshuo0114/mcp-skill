# 隐私边界：只读你的，不读别人的，也不帮别人读你的

这份文档回答你真正关心的三件事：

1. **启动时会不会夹带乱七八糟的东西？**
2. **审查器会不会去读别人的文件？别人会不会用它读你的？**
3. **mcp.json 里那些「指向」到底指向什么？**

---

## 一、三条硬边界（代码级，不是口头）

| 边界 | 含义 | 代码怎么钉 |
|---|---|---|
| 只读你的路径 | `review_open` / `review_scope(文件\|文件夹\|整仓)` 若路径落在 `/home/别人`、`/Users/别人`、`C:\Users\别人` → **硬拒绝** | `refuse_other_user_path` |
| 永不进别人家 | 整盘扫描**永远**跳过其他用户家目录；没有「含其他用户」选项；`include_other_users=True` → **硬拒绝** | `confirm.disk_options` 只剩「授权（永不进别人家）」/「不扫」；`enumerate_scope` 永远排除 |
| 不代别人启动你的隐私 | 别人在自己电脑上跑审查器，跑的是**他们自己的进程、他们自己的用户权限**，读不到你的家目录（除非他们用的是你的账号或管理员去破系统权限——那是操作系统问题，任何 App 都挡不住） | 报告写在你的 `~/.mcp-skill/`，不写进被审仓、不外传 |

审查器**没有联网工具、没有执行 shell 的工具、不上传文件**。密钥值在工具输出里隐去。

---

## 二、mcp.json 每一项「指向」什么（详细）

仓库里的 [`.cursor/mcp.json`](../.cursor/mcp.json) 现在是：

```json
{
  "mcpServers": {
    "file-reviewer": {
      "command": "${workspaceFolder}/.venv/bin/python",
      "args": ["-m", "servers.file_reviewer.server"],
      "cwd": "${workspaceFolder}",
      "env": {
        "MCP_SKILL_REPORT_DIR": "${userHome}/.mcp-skill/reports",
        "MCP_SKILL_ROLLBACK_DIR": "${userHome}/.mcp-skill/rollback"
      }
    }
  }
}
```

逐项拆开：

### 1. `command` = 用哪一个 Python 程序来启动审查器

| 写法 | 实际指向 | 干什么 | 不干什么 |
|---|---|---|---|
| `${workspaceFolder}/.venv/bin/python` | 本仓库目录下的 `.venv` 虚拟环境里的解释器（Windows 是 `.venv/Scripts/python.exe`） | 只负责**跑**审查器代码 | **不是**「允许读的文件夹」；**不是**网络地址；**不是**别人的路径 |
| 旧写法 `python3` | 系统 PATH 里碰巧叫 python3 的那个 | 同上，但可能和你装包用的不是同一个，且可能带一堆系统里别的包 | 同上 |

`${workspaceFolder}` = Cursor 当前打开的那个文件夹。方式 A 打开的是 `mcp-skill` 自己，所以展开后类似：

`/Users/你/mcp-skill/.venv/bin/python`

**为什么要用 `.venv`（防「启动夹带」）：**

- 新建的 `.venv` 里**几乎是空的**，再 `python -m pip install -e .` 只装本仓库声明的依赖：`mcp`、`pyyaml`（见 `pyproject.toml`）。
- 系统自带的 `python3` 往往已经装过很多包；那些包里若有人塞过 `.pth` 自动执行、或奇怪依赖，等于启动时「夹带」。
- `.venv` 在 `.gitignore` 里，**不会被提交进仓库**，别人 clone 你的仓拿不到你的虚拟环境内容。

所以：改 `command` 指向 `.venv`，是为了「启动干净、装包一致」，**不是**授权去读某个目录，更不是去读别人。

### 2. `args` = 启动时带哪些参数

固定为：`["-m", "servers.file_reviewer.server"]`

含义：用上面那个 Python，加载本仓库里的模块 `servers.file_reviewer.server`（审查器本体）。

**没有** `curl`、没有 `bash -c`、没有远程 URL、没有「先下载再跑」。别人若把这里改成乱七八糟的命令，那是**他们自己的 mcp.json 被篡改**——你应只信任你自己仓库里这份配置，并在 Cursor Settings → MCP 里看实际启动命令。

### 3. `cwd` = 进程的工作目录

指向 **mcp-skill 仓库根**（方式 A 用 `${workspaceFolder}`；方式 B 写成 mcp-skill 的绝对路径）。

只影响 Python 去哪找 `servers.file_reviewer` 这个包。  
**不是**「默认审查哪个项目」。被审路径要你在对话里用 `review_open(path=…)` 明确给出。

### 4. `env` 里的两个目录

| 变量 | 指向 | 存什么 |
|---|---|---|
| `MCP_SKILL_REPORT_DIR` → `${userHome}/.mcp-skill/reports` | **你自己的**用户目录下 | 审查报告（中文 markdown） |
| `MCP_SKILL_ROLLBACK_DIR` → `${userHome}/.mcp-skill/rollback` | **你自己的**用户目录下 | 普通修复的回滚备份（恶意内容故意不备份） |

`${userHome}` = 当前登录用户的家目录（你的，不是别人的）。  
报告**故意不写进被审网站/仓库**，避免审查记录跟着网站一起被上传。

## 三、「不要启动夹带」我们怎么做

| 风险 | 做法 |
|---|---|
| 系统 Python 里杂包 / `.pth` 自动执行 | 用新建 `.venv`，`command` 指向它 |
| mcp.json 被改成危险启动命令 | 打开本仓自带配置；Settings → MCP 核对 command/args；不可信三组会审 `.cursor/mcp.json` |
| 依赖从奇怪 URL 装 | 只用 `python -m pip install -e .`（读本仓库 `pyproject.toml`），不要 `pip install https://…` |
| 被审项目里的「先运行我」 | 硬规矩：文件内指令不当指令；审查器本身不执行被审目录里的脚本 |

## 四、「不要读别人 / 不要让别人读我」我们怎么做

### 不读别人

- 路径落在其他用户家目录 → 工具直接 `PermissionError`，没有「再确认一次就放行」。
- 整盘选项里**已删除**「含其他用户目录」；说「含其他用户」会当成「不扫」。
- 参数 `include_other_users=True` → 直接拒绝。

### 不帮别人读你

- 别人 clone 了 `mcp-skill`，在他们电脑上启动，进程跑在**他们的用户**下，OS 默认读不到你的 `~/`。
- 你的报告在 `~/.mcp-skill/`；不要把这个目录拷给别人、不要提交进公开仓。
- **做不到的**：若有人已经登录了你的账号、或有管理员权限、或你把文件放到了人人可读的共享盘——那是操作系统权限问题。审查器不能替代锁屏和账号隔离。我们如实说这一点，不装「绝对防别人」。

### 云端 Agent 额外提醒

把仓库交给 Cloud Agent 时，Agent 能看到的是**挂进那个环境的仓库内容**。不要把密钥、别人隐私、整盘导出塞进要给云端的副本。本机挂 MCP 审本机文件夹，数据不出你的电脑。
