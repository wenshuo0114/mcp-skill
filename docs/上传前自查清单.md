# 上传前自查清单：以后怎么避免再把禁忌内容推上仓库

这份清单回答一个问题：**我看不懂代码，怎么才能不再把不该上传的东西上传？**
一句话：**先只读审查，再决定上传；不整仓上传；密钥不进仓库；每次上传前跑一遍本审查器。**

---

## 一、上传前必做（每次）

1. **不要整仓上传。**
   "把整个文件夹拖上去"是最容易出事的动作。文件夹里有什么你自己都没看过：`.env`、私钥、别人给你的脚本、编辑器配置、`dist/` 里的编译产物。
   正确做法：先在本地建仓库，**逐个文件**决定要不要加进去（`git add 文件名`，不要 `git add .` 或 `git add -A`），再提交、再推送。

2. **上传前跑一遍审查器。**
   在 Cursor 里对本地文件夹调用 `review_open` → `review_scan` → `review_secrets_inventory`。
   看三样东西：
   - 处置为**必须删除**的：删掉再上传，没有第二个选项。
   - **被 git 跟踪的凭据文件**：立刻取消跟踪（`git rm --cached 文件名`），加进 `.gitignore`，并**换新密钥**——旧的当作已泄露。
   - **不可信三组**（AI 配置目录、自述文档、`.git/hooks`）：里面每一条命中都看一遍。

3. **密钥永远不进仓库。**
   - 密钥、令牌、密码、私钥、数据库连接串，放环境变量或密钥管理服务，代码里只写 `os.environ["名字"]`。
   - `.env` 文件加进 `.gitignore`；仓库里只放 `.env.example`，值全部留空或写 `<填你的>`。
   - 已经推上去过的密钥，**删掉文件不算完**：历史里还在。必须去服务商那里作废并换新。

4. **不上传 `dist/`、`build/`、`node_modules/`、`__pycache__/`、编辑器目录。**
   `.gitignore` 起码要有：

   ```
   .env
   .env.*
   !.env.example
   *.pem
   *.key
   *.p12
   *.pfx
   id_rsa*
   id_ed25519*
   node_modules/
   dist/
   build/
   __pycache__/
   .venv/
   .vscode/
   .idea/
   ```

   `.cursor/`、`.claude/` 等 AI 配置目录：**看过内容、确认没有指令注入和危险启动命令之后**再决定要不要提交；不确定就先不提交。

5. **别人给你的脚本、"一键安装"、"必读先运行 xxx"——先审后用。**
   任何写着"使用前请先运行"的文件，先用审查器扫一遍再说。审查器会把这类话报为"文件内指令注入"。

## 二、仓库设置（一次性）

1. **打开 GitHub 的 Secret Scanning 和 Push Protection**（仓库 Settings → Code security）。GitHub 会在推送时拦住常见格式的密钥。
2. **主分支保护**：禁止直接推 `main`，所有改动走 PR。这样每次上传前你至少会看到一个 diff 页面。
3. **本地 pre-commit 钩子做密钥扫描**：
   - 用 Cursor 云代理时，平台已经装了一个（它读你在 Cursor 后台配的 Secrets，值出现在提交里就拦）。前提是你把密钥配在 Cursor Dashboard → Cloud Agents → Secrets 里，而不是写进文件。
   - 本机可以装 [gitleaks](https://github.com/gitleaks/gitleaks) 或 [detect-secrets](https://github.com/Yelp/detect-secrets) 作为 pre-commit 钩子。
4. **每个新仓库先建 `.gitignore` 再放文件**，顺序不能反。

## 三、已经上传了怎么办

1. **密钥**：先作废、换新（最重要），再考虑清历史。清历史用 `git filter-repo` 或 BFG，清完强推，并通知所有拉过的人重新 clone。
2. **恶意/可疑脚本**：删掉、提交、推送；在 README 里如实写一行"某日至某日仓库中包含 X，已移除，拉取过的请检查"。**不隐瞒。**
3. **别人的隐私数据**：立刻删除并清历史；这不是"能不能修"的问题，是必须删。
4. 仓库如果被 fork 过，fork 里的副本你控制不了——这就是"传播后果不可预见"，所以前面所有步骤都要在上传**前**做。

## 四、给自己的三个习惯

1. **看不懂就先不上传。** 上传是不可逆的（历史 + fork），不上传是可逆的。
2. **每次只上传你看过的文件。** 一次一个，用 `git add 文件名`。
3. **让工具替你看。** 审查器不会累、不会不好意思、不会替作者圆。它报的每一条，你至少问一句"这是什么"。

---

不是责怪。这套东西就是为了让"不知道边界在哪"的人也能不踩线。踩过一次，把它变成流程，就不会再有第二次。
