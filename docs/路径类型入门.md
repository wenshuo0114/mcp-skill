# 路径类型入门：这个文件到底在哪里？

给不熟悉电脑路径的人看。审查报告里会出现 `~/.grok`、`/home/xx/.codex`、`C:\Users\xx\.vscode` 这样的路径——这份文档回答三件事：**它在哪台机器上、在那台机器的什么地方、怎么打开它**。

审查器的 `review_explain_paths` 工具会对每条路径自动给出这些判断；判断不了的会写"判断不了"。这里讲的是判断背后的常识，让你自己也能看懂。

---

## 一、先分清"哪台机器"

同一个路径写法，可能在完全不同的机器上。看路径本身分不出来，要看**你现在操作的是什么**。

| 你在哪里操作 | 路径指的是 | 怎么确认 |
|---|---|---|
| 自己笔记本上的终端 / 编辑器 | 本地磁盘 | 审查器"环境来源"写 `物理机或未知（未见虚拟化信号）` |
| 笔记本里开的虚拟机（Hyper-V、VMware、VirtualBox） | **虚拟机的盘**，它是宿主上的一个大文件，不是笔记本硬盘本身 | 环境来源写 `虚拟机内（Hyper-V（微软））` 之类；写 `厂商未知` 就是查不出是谁的 |
| Windows 里的 WSL（Ubuntu 窗口） | `/` 开头的是 Linux 侧；`/mnt/c/...` 才是 Windows 的 C 盘 | 环境来源写 `WSL 内` |
| Docker / 云端 Agent 容器 | 容器的盘，容器一销毁就没了 | 环境来源写 `容器内` |
| SSH 连上的服务器（VPS） | 那台服务器的盘 | 你的终端提示符是别的主机名；环境来源的主机名不是你笔记本 |
| 通过挂载看到的远程目录 | 不在当前机器上 | 环境来源"能触达外部的挂载"里列出（sshfs / cifs / 9p / virtiofs） |

**一句话**：先看报告顶部的「环境来源」，再看路径。

## 二、再分清"什么地方"

### 1. Git 仓库（本地副本）
- 特征：目录里（或上级目录里）有一个 `.git` 文件夹。
- 它是**你电脑上的一份副本**。改它不会自动改到网上，要 `git push` 才会。
- `.git/config` 里的 `url =` 一行告诉你它对应网上哪个仓库。

### 2. 云仓库（GitHub / GitLab / Gitee 等）
- 就是上面那个 `url` 指向的地方，在别人的服务器上。
- 常见品牌：`github.com`（GitHub，微软旗下）、`gitlab.com`、`gitee.com`（码云）、`dev.azure.com`（Azure DevOps）、`codeup.aliyun.com`（阿里云）、`coding.net`（腾讯）。
- **注意**：推送上去的东西会进历史，删掉本地文件不等于网上没了。密钥一旦推上去就当已泄露，要换。

### 3. 部署到 Cloudflare 的网页（Workers / Pages）
- 特征：仓库根目录有 `wrangler.toml` / `wrangler.json`，或 `_worker.js`、`_routes.json`。
- 这些代码会跑在 Cloudflare 的边缘服务器上，**用户访问你网址时执行的就是它**。
- 同类：`vercel.json`（Vercel）、`netlify.toml`（Netlify）、`firebase.json`（Firebase）、`fly.toml`（Fly.io）。

### 4. VPS / 服务器系统目录
- 路径以 `/etc`、`/var`、`/srv`、`/opt`、`/usr` 开头，或 Windows 的 `C:\Windows`、`C:\ProgramData`。
- 这些不属于任何一个"项目"，属于操作系统。改错会影响整台机器。
- `/etc/systemd/system`、`/etc/cron.d`、`/etc/ld.so.preload` 是持久化重灾区，见《持久化位置清单》。

### 5. 你的用户目录（home）
- Linux/macOS：`/home/你的名字` 或 `/Users/你的名字`，写作 `~`。
- Windows：`C:\Users\你的名字`，写作 `%USERPROFILE%`。
- 以点开头的子目录（`.ssh`、`.cursor`、`.config`）是**隐藏目录**，文件管理器默认不显示。

### 6. 其他用户的目录

- 特征：`/home/别人`、`/Users/别人`、`C:\Users\别人`（不是你自己的用户名）。
- **审查器硬拒绝**：`review_open` / `review_scope` 不会读这里；整盘也永远跳过；没有「授权后可读」的旁路。
- 那是别人的隐私。要审，只能由那个用户在自己的账号下自己打开审查器。详见 [隐私边界.md](隐私边界.md)。

### 7. 虚拟机里的用户目录- 看起来和第 5 条一模一样，区别只在"环境来源"写着虚拟机。
- 虚拟机里的 `~` 不是宿主的 `~`。两边各有一套 `.ssh`、`.cursor`。

## 三、常见的点开头目录是什么

| 路径 | 是什么 | 为什么要审 |
|---|---|---|
| `~/.ssh` | SSH 密钥。`id_rsa`/`id_ed25519` 是私钥 = 你的登录密码；`authorized_keys` 是允许进来的公钥 | 私钥泄露 = 别人能登你的服务器；`authorized_keys` 多一行 = 多一个人能进 |
| `~/.cursor` `~/.vscode` `~/.config/Code` | 编辑器配置：插件、设置、MCP 服务器、技能 | 编辑器会按里面的配置**自动启动进程** |
| `~/.claude` `~/.codex` `~/.gemini` `~/.grok` | 各家 AI 助手的配置、技能、记忆 | 里面的文字会被 AI 当指令读——投毒首选 |
| `~/.bashrc` `~/.zshrc` `~/.profile` | 每次打开终端自动执行的脚本 | 加一行就是每次开终端都跑 |
| `~/.config/autostart` | 桌面登录自启 | 同上 |
| `~/.aws` `~/.kube` `~/.docker` `~/.npmrc` `~/.pypirc` | 各类云服务/发布平台的凭据 | 泄露 = 别人能用你的账号 |
| `~/.gitconfig` | 全局 git 配置 | `hooksPath`、别名可以执行任意命令 |
| `~/.local/lib/pythonX/site-packages` `~/.venv` | Python 第三方包 | `*.pth` 文件里的 `import` 行在**每次启动 Python 时自动执行** |
| `~/.config/google-chrome` `~/.mozilla/firefox` | 浏览器配置、扩展、保存的密码 | 扩展能看到你所有网页；`user.js`/策略能锁死主页和代理 |

## 四、怎么打开它（只在你现有权限内）

- **复制粘贴**：报告里的路径可以直接粘到文件管理器地址栏（Windows 资源管理器、macOS 访达 `Cmd+Shift+G`、Linux 文件管理器 `Ctrl+L`）。
- **点击**：报告里 `file:///...` 形式的链接，多数编辑器/浏览器可点。
- **命令**：
  - Windows：`explorer /select,"C:\完整\路径"`
  - macOS：`open -R "/完整/路径"`
  - Linux：`xdg-open "/所在/目录"`
- **看不到隐藏文件**：Linux/macOS 文件管理器按 `Ctrl+H`（访达 `Cmd+Shift+.`）；终端用 `ls -la`；Windows 资源管理器"查看 → 显示 → 隐藏的项目"。

**打不开怎么办**：
- 报告写"不存在"：它可能已被删、挂载没就绪、或在别的机器上。先看环境来源。
- 报告写"无权限"：审查器**不会帮你绕过**。如果这台机器是你的且你有管理员账户，你自己决定是否以管理员身份重开编辑器；如果属于别人，需要那个人授权。
- 报告写"属于其他用户"：停。那是别人的目录。

## 五、三个常见误会

1. **"我把文件删了，网上也没了"** —— 不对。推过的东西在云仓库历史里，要按平台流程清历史 + 换密钥。
2. **"虚拟机里的东西是笔记本上的东西"** —— 不对。虚拟机有自己的一套盘和用户目录；宿主是另一台"机器"。
3. **"我看不见 `.ssh`，所以没有"** —— 不对。点开头的是隐藏目录，默认不显示。

---

*本文只讲"在哪、是什么、怎么打开"，不讲任何绕过权限的方法。判断不了的地方，审查器会写"判断不了"，请以你在机器上实际看到的为准。*
